Sobre o FUTSTATS

Um site de estatísticas de futebol inspirado no SofaScore, feito com HTML, CSS e JavaScript puro: sem framework, sem etapa de build e sem servidor. Aqui está como ele funciona por dentro e as partes que deram mais trabalho.

Arquitetura

Cada página HTML carrega os mesmos módulos, em camadas. Nenhuma camada conhece a de cima:

  1. Dados estáticos elencos.js · clubes.js · competicoes.js · calendario.jsElencos oficiais, clubes, formatos e o calendário da Copa, extraídos da Wikipedia.
  2. Regras e armazenamento db.jsClassificação, desempates, mata-mata, estatísticas, notas e backup. Lê e grava no localStorage, com cache em memória.
  3. Componentes de interface ui.jsTopo, busca (Ctrl+K), tabelas, campinho e gráficos em SVG desenhados à mão.
  4. Página main.js · jogo.js · simulador.js · bolao.js…Cada uma monta a própria tela a partir das camadas de baixo.

O contexto (o campeonato escolhido no topo) filtra todas as consultas: DB.Jogos.all() devolve só os jogos do campeonato aberto, e o mesmo código serve à Copa, às ligas de pontos corridos, à fase de liga da Champions e aos grupos da Libertadores.

Os visitantes recebem os dados pelo arquivo js/dados.js, gerado pelo painel e publicado no repositório. Se ele for mais novo do que o que o navegador já tem, substitui os dados locais.

Decisões técnicas

  • JavaScript puro, sem build. O site abre direto do GitHub Pages e o código que roda é o código que está no repositório.
  • Cache em memória sobre o localStorage. Com milhares de jogadores, reconverter o JSON a cada consulta deixava as páginas lentas.
  • Dados grandes sob demanda. Os elencos (~500 KB) só são baixados na primeira visita, para montar a base. Depois, tudo vem do armazenamento local.
  • Gráficos em SVG próprio. Linha, barras, radar e o mapa das sedes são gerados como texto, sem bibliotecas, e seguem o tema claro/escuro.
  • Testes sem dependências. O node:test carrega os mesmos arquivos do site num contexto isolado, com um localStorage em memória (npm test).

Desafios

  • Desempate da FIFA. Times empatados disputam uma “mini-liga” só entre eles. Se ela separar parte do grupo, o critério é reaplicado só aos que continuam empatados. Daí para saldo geral, gols, fair play e ranking. A função é recursiva e tem testes para cada caso.
  • Os 8 melhores terceiros. Cada vaga dos 32avos aceita terceiros de só 5 grupos. Em vez da tabela de 495 combinações do regulamento, um backtracking encontra uma distribuição válida.
  • Monte Carlo no navegador. 10 mil simulações da Copa (fase de grupos e mata-mata) rodam em poucos segundos, em blocos, sem travar a tela. Medindo, os gargalos eram recalcular os times de cada grupo e ordenar datas: com cache e comparação de texto, cada simulação caiu de ~0,9 ms para ~0,25 ms.
  • Bolão sem servidor. Os palpites viajam no próprio link (JSON em base64url). Cada pessoa monta o ranking com os links que recebe.

Limites conhecidos

  • O painel é um modo demonstração: sem back-end, a senha só evita edições por engano. As mudanças valem só para o navegador de quem edita, até virarem um novo js/dados.js.
  • As probabilidades vêm de um modelo simples (Elo + Poisson). Servem para explorar cenários, não para apostar.
  • As notas dos jogadores são calculadas a partir dos lances cadastrados (gols, assistências, cartões, gols sofridos), não de dados de rastreamento.
